Study handbook

AlumniConnect

A multi-college alumni network built with Next.js 15, React 19 and SQLite. Every fact here is checked against the code at commit 2c27616 (7989a52 plus the badge and admin-gate fixes); numbers come from docs/smoke-check-output.txt and from lint and build runs. The Markdown sources are ARCHITECTURE.md, CODEBASE_GUIDE.md and INTERVIEW_PREP.md in the same folder.

30-second pitch, say it aloud

"Colleges lose touch with their graduates, and students have no private way to reach alumni for referrals or advice. AlumniConnect gives each college its own private network: you sign up with your college email, then search the directory, connect, message, share jobs, RSVP to events and request mentorship. One deployment serves many colleges, and a platform admin can onboard or switch off a college without touching anyone else. The part I'd like to talk about is the access-control design: the session token only proves who you are, and every request re-checks your role, your account and your college in the database, so revoking access is immediate, and every query is scoped to your college."

Token says who, DB says what

Middleware verifies the JWT; every handler re-reads user, role and college from SQLite.

Every query carries a college

Shared-schema multi-tenancy; cross-college lookups return 404, not 403.

Invariants live in transactions and constraints

RSVP capacity, mutual requests and the superadmin rule are atomic or enforced by CHECK/UNIQUE.

One error dialect

handler() + validate() give every route the same { error, details } shape.

The 60-second mental model

The app does three jobs:

  1. Gatekeeping: who you are (JWT cookie) and what you may do right now (role and active status from the database).
  2. Tenant-scoped CRUD: directory, connections, messages, jobs, events, mentorship and notifications, all filtered to your college.
  3. Two-level administration: college admins manage one college; the platform admin adds colleges, appoints admins and switches colleges on or off.

It is split this way because Next.js middleware runs on the Edge runtime and cannot open SQLite, so it does only cheap token work. Everything that needs data runs in Node route handlers and server components that share lib/. One process, one database file, nothing else to coordinate.

One sentence

The token says who you are, the database says what you may do, and every query carries your college id.

How it works end to end

Send a connection request

  1. ConnectButton.connect() calls api("/api/connections", POST {user_id}).
  2. middleware.js verifies the JWT; no token means 401.
  3. POST in app/api/connections/route.js runs inside handler(); requireUser() re-reads the user and college.
  4. validate() checks user_id; connecting to yourself is 422.
  5. getColleague() loads the target only if same college and active, else 404.
  6. In transaction(), findConnection() looks both ways: accepted is 409, mine pending is 409, theirs pending gets accepted, none inserts pending.
  7. notify() writes a notification; response 201 { connection: { id, status } }.

RSVP to a capacity-limited event

  1. events/page.js posts to /api/events/:id/rsvp.
  2. loadEvent() requires same college (404) and a future start (409).
  3. In one transaction: already registered is 409, COUNT(*) >= capacity is 409 "This event is full", else insert.
  4. Measured: 5 concurrent RSVPs to capacity 1 gave 1 x 201 and 4 x 409.

Log in

  1. Validate email and password (max 72).
  2. rateLimit("login:ip:email", 10 per 15 min) before touching the DB.
  3. LEFT JOIN colleges so the college-less superadmin is found.
  4. bcrypt.compare against the real hash or DUMMY_HASH; same 401 either way.
  5. 403 if the user or (for non-superadmins) the college is inactive.
  6. signSession() sets a 7-day cookie; response carries redirect; the page applies safeNext().

Deactivate a member

  1. UserManagement.js sends PATCH /api/admin/users/:id {is_active:false}.
  2. Middleware only checks the JWT is valid; requireRole("admin") checks the role in the DB (the token's role can be stale).
  3. Not yourself (422); target must be in your college (404).
  4. The target's next request fails getCurrentUser(): API 401, pages redirect to /login. Verified.

Chat with polling

  1. Open thread: GET /api/messages/:userId returns up to 200 messages and marks theirs read.
  2. Every 4 s: GET ?after=<lastId>; a Set of ids dedupes.
  3. Send: POST requires an accepted connection, else 403.
  4. Conversation list every 15 s; nav badges every 20 s via /api/summary.

The ideas worth understanding deeply

7.1 Two-layer authorization

  • Problem: a JWT cannot be revoked; it stays valid until it expires (7 days here).
  • Solution: middleware.js verifies the signature (cheap, Edge). requireUser() in lib/session.js re-reads the user and college from SQLite on every API call and every dashboard render.
  • Alternative: server-side session table checked in middleware, or short-lived access tokens plus refresh tokens.
  • Trade-off: one indexed DB read per request. Middleware must not make authorization decisions from the token's role, because it goes stale; the college-admin gate was removed from middleware for exactly that reason.
Interview sentence

"The token only proves identity; authorization is re-derived from the database on every request, so deactivating a user or a college takes effect on their next click."

7.2 Multi-tenancy by column, 404 not 403

  • Problem: many colleges share one database; nobody may see another college's data.
  • Solution: college_id on users, jobs and events; every college-scoped query filters by me.collegeId; getColleague() is the single gate for user-to-user actions. A row from another college is "not found".
  • Alternative: database-per-tenant or PostgreSQL row-level security.
  • Trade-off: isolation depends on every query remembering the filter; there is no database-enforced policy. Messages, connections and notifications are scoped by user id instead, and stay correct because the users at both ends were checked through getColleague() when the row was created.
Interview sentence

"Tenant isolation is a shared-schema design with a college_id filter, and cross-tenant lookups return 404 so they don't even confirm the resource exists."

7.3 Race-free capacity check

  • Problem: two people take the last seat at the same moment.
  • Solution: in app/api/events/[id]/rsvp/route.js, count and insert run inside one transaction(). better-sqlite3 is synchronous, so the whole transaction executes without yielding the event loop.
  • Alternative: a conditional INSERT ... SELECT ... WHERE (SELECT COUNT(*) ...) < capacity, or SELECT ... FOR UPDATE on PostgreSQL.
  • Trade-off: correct only while writes are serialised by one process plus SQLite's lock. Measured: 5 concurrent attempts on capacity 1 gave one 201 and four 409s.
Interview sentence

"The check and the insert are one atomic unit; on Postgres I'd lock the event row or make the insert conditional."

7.4 Mutual connection requests

  • Problem: A requests B while B already requested A; the schema's UNIQUE (requester_id, addressee_id) would allow both rows.
  • Solution: findConnection() searches both directions inside a transaction; if B already asked, A's request accepts it.
  • Alternative: store pairs canonically (LEAST(a,b), GREATEST(a,b)) with a unique index.
  • Trade-off: the invariant lives in code, so the mentorship accept path also had to use findConnection().
Interview sentence

"Pair uniqueness in either direction is enforced in the transaction, and a crossing request becomes an accept instead of a duplicate."

7.5 Mentorship as a state machine

  • Problem: many actions, each legal only for one party in one state.
  • Solution: TRANSITIONS in app/api/mentorship/[id]/route.js: { by, from, to } per action. Wrong actor -> 403, wrong state -> 409; cancel deletes.
  • Alternative: nested ifs per action.
  • Trade-off: compact and auditable, but the status check and the update are not inside one transaction, so two simultaneous transitions could both pass the check (low risk, one process).
Interview sentence

"Every legal move is one row in a table, so adding a state is a data change, and illegal moves get a 409."

7.6 Timing-safe login and enumeration

  • Problem: if unknown emails return faster, an attacker can list registered users.
  • Solution: DUMMY_HASH precomputed at module load; bcrypt.compare always runs; one generic 401 message.
  • Trade-off: registration still says "An account with this email already exists" (409), so enumeration is possible there; rate limiting slows it.
Interview sentence

"Login does the same bcrypt work whether or not the account exists, so response time doesn't leak which emails are registered."

7.7 One validator, one error shape

  • Problem: consistent 4xx responses the UI can map to fields.
  • Solution: validate() returns a whitelisted object or throws HttpError(422, firstMessage, details); handler() turns it into { error, details }; ApiError on the client exposes details; forms pass errors.<field> to Field.
  • Alternative: zod schemas shared with the client.
  • Trade-off: small and dependency-free, but validation rules are not shared with the browser.
Interview sentence

"Every route speaks the same error dialect, so any form can show server-side field errors without custom code."

7.8 Schema on startup, and a guard for what can't migrate

  • Problem: zero-setup local runs, but schema evolution.
  • Solution: openDatabase() re-applies idempotent schema.sql on every start and seeds an empty DB. Because SQLite cannot alter a CHECK constraint, it detects the pre-platform-admin schema and throws with a "run db:reset" message.
  • Alternative: a migration tool.
  • Trade-off: fine for demo data; destroys data on schema change.
Interview sentence

"The schema is applied idempotently at boot; there are no migrations yet, and the app fails loudly rather than run on an incompatible schema."

7.9 A constraint that encodes the tenancy rule

  • CHECK ((role = 'superadmin') = (college_id IS NULL)) in users: platform admins have no college and everyone else must have one. Bad data cannot be inserted even by a buggy route.
Interview sentence

"The rule that only platform admins live outside a college is a database CHECK, not just application logic."

7.10 Cursor polling for chat

  • Problem: near-real-time chat without WebSockets.
  • Solution: the client remembers the last message id (lastIdRef) and asks for ?after=<id>; ids are monotonic (AUTOINCREMENT), so no message is missed or repeated; a Set dedupes the optimistic append.
  • Trade-off: latency up to 4 s; about 22 background requests per minute per user with a chat open.
Interview sentence

"Polling uses the message id as a cursor, so each poll returns only new rows and is cheap with the (sender, recipient, id) index."

7.11 Server components for read-heavy pages

  • app/dashboard/page.js, admin/page.js and platform/page.js query SQLite directly instead of calling their own API. No extra HTTP hop and no loading spinner on first paint; interactive pages stay client components with useApi.
  • Trade-off: two code paths read the same data (SQL in pages and in routes) and can drift.

The code, function by function

Open a fold, read the summary, then open the real file and find each name.

Edge

middleware.js
  • Responsibility: authentication gate for all non-static paths, the platform (superadmin) gate, superadmin confinement, security headers.
  • Key items: PUBLIC_API, AUTH_PAGES, withSecurityHeaders(), config.matcher (excludes _next/static, _next/image, favicon.ico, robots.txt).
  • Depends on: lib/auth.js only (Edge-safe).
  • Gotcha: anything it reads from the JWT can be stale. That is why it no longer gates /api/admin or /dashboard/admin on the token's role (a promoted admin used to be blocked until re-login); those are checked against the database by requireRole("admin") and app/dashboard/admin/page.js.

lib (server)

lib/auth.js
  • signSession(), verifySession(), sessionCookieOptions(), constants SESSION_COOKIE = "ac_session", SESSION_TTL_SECONDS (7 days).
  • getSecret() throws in production without JWT_SECRET, and for any secret under 32 chars.
  • Used by middleware, login, register, logout and lib/session.js.
  • Gotcha: verifySession() swallows all errors and returns null, so a misconfigured secret looks like "logged out".
lib/session.js
  • getCurrentUser (React cache()), requireUser(), requireRole(...roles).
  • The query requires u.is_active = 1 AND (u.role = 'superadmin' OR c.is_active = 1); returns { id, email, role, collegeId, collegeName, fullName }.
  • Used by every route handler and every server page.
  • Gotcha: cache() dedupes per request only; there is no cross-request caching, so each API call costs one indexed primary-key lookup.
lib/db.js
  • getDb() caches one better-sqlite3 handle on globalThis.__alumniConnectDb so dev hot reloads do not leak handles.
  • Helpers all, get, run prepare and run a statement; transaction(fn) wraps db.transaction(fn)().
  • Gotcha: statements are prepared on every call (no statement cache). Cheap for SQLite, but a known micro-optimisation.
lib/http.js
  • HttpError(status, message, details), handler(fn), json, readJson (400 unless a JSON object), parseId (404 unless positive integer), getPagination (default 20, max 50).
  • Gotcha: handler() turns any non-HttpError into 500, including SQLite UNIQUE violations (see section 12).
lib/validation.js
  • validate(input, rules, { partial }) supports string, password (not trimmed), email (lower-cased), url (http/https only), int, bool, enum, datetime (normalised to ISO).
  • Returns only declared fields: a whitelist, which is what makes the dynamic UPDATE in profiles/me safe.
  • PASSWORD_RULE (8-72), assertStrongPassword() (letter + digit).
  • Gotcha: with partial: true, an explicitly empty value becomes null (or false for bool) and is written; omitted fields are left unchanged.
lib/domain.js
  • getColleague(), findConnection(), CONNECTION_STATUS_SQL, notify(), CAN_POST_JOBS, CAN_CREATE_EVENTS, CAN_MENTOR, JOB_TYPES, EVENT_TYPES, DOMAIN_RULE, normalizeDomain().
  • Used by connections, mentorship, messages, profiles, events, jobs and platform routes.
  • Gotcha: CONNECTION_STATUS_SQL assumes the query aliases the connection join as c and binds @me.
lib/rate-limit.js
  • rateLimit(key, { limit, windowMs }) fixed window in a Map; sweeps expired buckets when the map exceeds 10,000 keys. clientIp() reads x-forwarded-for, then x-real-ip, else "local".
  • Gotcha: successful attempts count too, and the IP comes from a client-controlled header (verified bypass).

**lib/format.js** (server and client)

  • parseDate() treats SQLite YYYY-MM-DD HH:MM:SS as UTC; timeAgo, formatDate, formatDateTime, initials, ROLE_LABELS, JOB_TYPE_LABELS, EVENT_TYPE_LABELS.
  • Gotcha: two timestamp formats coexist: datetime('now') (space, no zone) for created_at, ISO-8601 with Z for events.starts_at. Comparisons only ever compare like with like.

Database

database/schema.sql

10 tables, 10 indexes, all CREATE ... IF NOT EXISTS. Key constraints: users.email UNIQUE COLLATE NOCASE; CHECK ((role = 'superadmin') = (college_id IS NULL)); connections UNIQUE (requester_id, addressee_id) and CHECK (requester_id <> addressee_id); event_rsvps PRIMARY KEY (event_id, user_id); status CHECKs on connections, jobs, mentorship; ON DELETE CASCADE everywhere.

database/init.js

CommonJS so both Next.js and scripts/db-reset.js can load it. openDatabase() creates the directory, sets journal_mode = WAL, foreign_keys = ON, busy_timeout = 5000, refuses an outdated schema, applies schema.sql, and seeds when colleges is empty unless SEED_DEMO_DATA=false.

database/seed.js

3 colleges (Riverside inactive), 21 users across 5 roles, connections, messages, jobs, 6 events (the career fair is full at capacity 3), mentorship requests in every status, notifications. One bcrypt hash reused for all demo accounts. All in one transaction.

scripts/db-reset.js

deletes the DB and its -wal / -shm files, reopens (which re-seeds), prints the user count.

Bug stories

Fake persistence in the original code.

  • Situation: settings and password forms showed success toasts.
  • Root cause: setTimeout stubs instead of API calls (app/dashboard/settings/page.js at efc62ee).
  • Fix: real route handlers plus lib/client.js api() in commit dece944.
  • Lesson: a green toast is not evidence; check the network tab and the database.

Two databases pretending to be one.

  • Situation: lib/db.js translated PostgreSQL $1 placeholders to ? with a regex, lib/sqlite-db.js had its own inline schema, database/schema.sql another, and src/pages/Server.js was an Express + MongoDB server.
  • Fix: one schema, one openDatabase(), one thin lib/db.js; legacy src/ deleted.
  • Lesson: cut scope to something coherent before adding features.

A user with no college.

  • Situation: adding the platform admin.
  • Root cause: users.college_id NOT NULL and an inner JOIN colleges in getCurrentUser().
  • Fix (f5f0e52): nullable college_id with a CHECK tying it to superadmin, LEFT JOIN plus (u.role = 'superadmin' OR c.is_active = 1), and an out-of-date-schema guard in database/init.js because SQLite cannot alter CHECK constraints.
  • Lesson: a new role is a data-model change, not a new string in an enum.

JWT library vs Edge runtime.

  • Root cause: jsonwebtoken needs Node crypto; middleware runs on Edge.
  • Fix: jose in lib/auth.js.
  • Lesson: know which runtime each file runs in.

Nav badge vs Connections page (found and fixed while documenting).

  • Situation: after deactivating a user who had a pending request, the badge said 1 and the Connections page said 0.
  • Root cause: app/api/summary/route.js did not join users.is_active, unlike app/api/connections/route.js.
  • Fix: both badge sub-counts (requests and unread messages) now join the other user and require is_active = 1.
  • Lesson: two queries for the same concept drift; write a check that compares them.

Promoted admins locked out (found and fixed while documenting).

  • Situation: a member promoted to admin got 403 on /api/admin/users until they logged in again.
  • Root cause: middleware.js gated admin routes on the role inside the JWT, which only changes at login.
  • Fix: removed that gate; requireRole("admin") in each handler and the role check in app/dashboard/admin/page.js decide, against the database. Platform routes keep their gate because nobody can be promoted to superadmin.
  • Lesson: middleware should authenticate; authorization belongs where the current data is.

What is AlumniConnect in one sentence?Project framing

A multi-college alumni network where each college's students, alumni and faculty get a private directory, messaging, jobs, events and mentorship, and a platform admin onboards colleges on shared infrastructure.

What did you personally build versus inherit?Project framing

The project started as a codebase that did not work: fake setTimeout saves, two database layers and leftover Express/MongoDB code. Commit dece944 rebuilt the data layer, auth, all APIs and the UI; f5f0e52 added the platform admin. I used AI assistance, and I reviewed and tested what went in; I can walk through any file.

What was the hardest part?Project framing

Deciding what to cut. The original had forums, maps, analytics and achievements that were mostly mock pages. I reduced it to a coherent core where every feature works end to end, then added the platform-admin layer, which forced a data-model change.

Why should an interviewer care about this project?Project framing

It shows access control done carefully: revocation without a token blacklist, tenant isolation, race-free capacity checks and consistent error semantics, all in a small codebase I can explain line by line.

What would you do differently if you started again?Project framing

Write the test script on day one and run it in CI, keep authentication-only logic in middleware and all authorization in handlers, and start on PostgreSQL with migrations if real users were expected.

Who are the users and what can each role do?Project framing

Students and alumni self-register; faculty and admins are created by an admin. Alumni, faculty and admins can post jobs and create events; alumni and faculty can mentor. College admins manage members of their own college; the platform admin manages colleges and appoints admins.

Why Next.js instead of a separate Express backend?Web and backend fundamentals

One codebase and one deploy, shared helpers between pages and API, and server components that can read the database directly for fast first render. The cost is coupling: the UI and API scale and deploy together.

What is the difference between a server component and a client component here?Web and backend fundamentals

app/dashboard/page.js is a server component: it runs SQL with all()/get() and sends HTML. app/dashboard/directory/page.js has "use client" and calls /api/profiles from the browser because it needs live filtering.

Why does the middleware not query the database?Web and backend fundamentals

Next.js middleware runs on the Edge runtime, which cannot load the native better-sqlite3 module or open a file. So middleware only verifies the token, and database checks happen in Node route handlers.

How are errors returned?Web and backend fundamentals

Every handler is wrapped in handler() from lib/http.js. A thrown HttpError becomes { error, details } with its status; unknown errors are logged with method and path and returned as a generic 500.

Which status codes do you use and when?Web and backend fundamentals

400 for a malformed body or bad filter, 401 not signed in, 403 signed in but not allowed, 404 not found or in another college, 409 conflicts such as duplicate requests, a full event or an illegal state change, 422 validation failures with field details, 429 rate limited.

Why 422 and not 400 for validation errors?Web and backend fundamentals

400 here means the request could not be parsed as a JSON object; 422 means it was well-formed but the values broke a rule. The UI uses the 422 details map to show errors next to fields.

How does pagination work?Web and backend fundamentals

getPagination() reads page and limit (default 20, capped at 50; routes override, for example 12 for the directory). The route reuses one where clause for COUNT(*) and the LIMIT/OFFSET query and returns { page, limit, total, totalPages }.

How does the client handle an expired session?Web and backend fundamentals

api() in lib/client.js sees a 401 from any non-auth endpoint and sets window.location to /login?next=<current path>. After login, safeNext() sends the user back only if the path is same-site.

Why SQLite? Isn't it a toy?Data and SQL

It is an ACID database with transactions, foreign keys and CHECK constraints, and it let the app run with npm install && npm run dev. The limit is a single host and a single writer at a time, which is the main reason it would move to PostgreSQL for real traffic.

Walk me through the schema.Data and SQL

Ten tables: colleges as tenants; users and a 1:1 profile; connections, messages, jobs, events with RSVPs, mentorship requests and notifications. Jobs and events carry college_id; social tables reference users. Cascading foreign keys and ten indexes on the common lookups.

How do you stop duplicate connections in both directions?Data and SQL

The schema has UNIQUE (requester_id, addressee_id), which only covers one direction. The POST handler uses findConnection() to look both ways inside a transaction, and if the other person already asked, it accepts that request instead of inserting.

What does WAL mode give you?Data and SQL

Readers do not block the writer and the writer does not block readers, which matters because the app polls constantly while users write messages. Writes are still serialised.

Why is foreign_keys = ON set explicitly?Data and SQL

SQLite ships with foreign key enforcement off for backward compatibility; without the pragma, ON DELETE CASCADE would silently do nothing.

How do you prevent SQL injection when building the profile UPDATE dynamically?Data and SQL

The column names come from Object.keys(data), and data is the output of validate(), which only returns keys declared in PROFILE_RULES. Values are bound as named parameters.

How does search work and how would it scale?Data and SQL

LIKE '%term%' over name, company, headline and skills, with wildcards escaped. A leading wildcard cannot use an index, so it is a full scan of the college's users; I would move to SQLite FTS5 or PostgreSQL full-text search.

How are schema changes handled?Data and SQL

They aren't migrated: schema.sql is applied idempotently on boot and npm run db:reset recreates the database. database/init.js detects the one known incompatible old schema and refuses to start with a clear message.

How do you know it works?Evaluation and testing

I ran a 52-check end-to-end script against a production build on a fresh database and all pass; two of those checks first failed and exposed real bugs, which I fixed. It covers authentication, cross-college isolation, roles, validation, capacity, the state machine and revocation. Lint passes and the production build succeeds.

Is there a test suite in the repo?Evaluation and testing

No. There is no test script and no CI; the smoke script lives in docs/ and is not wired into npm test. Adding Vitest units and running the smoke script in CI is the first thing I would do.

How did you test the race condition on event capacity?Evaluation and testing

I created an event with capacity 1 and fired five RSVPs from five signed-in users with Promise.all. Exactly one got 201 and four got 409 "This event is full".

What do your tests not cover?Evaluation and testing

The UI, multi-instance deployment, load, PostgreSQL behaviour, and the registration race on a duplicate email. They also mutate data, so they must run on a freshly seeded database.

What would you measure in production?Evaluation and testing

p95 latency of directory search and thread polling, request volume from polling per active user (about 22 per minute with a chat open), SQLite lock waits, failed-login and 429 rates, and weekly active users per college.

How would you scale this to many colleges and thousands of users?Systems and architecture

Move to PostgreSQL with a connection pool, put rate limits and pub/sub in Redis, run several stateless Next.js instances behind a load balancer, replace polling with Server-Sent Events, and add full-text search. The code already isolates SQL in route files and lib/db.js, so the change is mostly mechanical.

What breaks first under load?Systems and architecture

Polling volume and SQLite writes on one host. Every open chat polls every 4 s and every tab polls badges every 20 s, and all writes funnel through one file lock.

What happens if you run two instances against one SQLite file?Systems and architecture

Rate limits would be per instance, the globalThis handle is per process, and writers would contend for the file lock; network file systems make SQLite locking unreliable. It is a single-instance design.

Why polling and not WebSockets?Systems and architecture

It works on any host, including the Render free tier, and is easy to reason about. The cursor ?after=<id> makes each poll cheap. The cost is latency and wasted requests; SSE would be my next step.

How does the event capacity check stay correct under concurrency?Systems and architecture

Count and insert run in one better-sqlite3 transaction. The driver is synchronous, so nothing else runs on the event loop mid-transaction, and SQLite's write lock serialises writers. On PostgreSQL I'd lock the event row with SELECT ... FOR UPDATE or use a conditional insert.

Why server components for the dashboard and admin pages?Systems and architecture

They are read-heavy and need no interactivity on first paint, so querying the database directly avoids a client round trip and a loading state. The trade-off is that the same data is read in two places (pages and API routes) and can drift.

How is the mentorship workflow modelled?Systems and architecture

As a transition table: accept and decline by the mentor from pending, complete by either party from accepted, cancel by the mentee from pending (deletes the row). Wrong actor gives 403 and wrong state gives 409, and accepting connects the pair so they can message.

What is a single point of failure here?Systems and architecture

Everything: one process, one disk. On the free Render plan the disk is also ephemeral, so a restart resets data to the demo seed.

JWTs can't be revoked. How do you ban a user?Auth and security

The JWT only proves identity. requireUser() re-reads the user and their college on every request and rejects inactive ones, so a deactivated user gets 401 on their next API call. I verified that with an existing token.

Then is revocation fully solved?Auth and security

No. Logout only clears the cookie and a password change doesn't invalidate other sessions; a stolen token works for up to 7 days unless the account is deactivated. A token_version column checked in getCurrentUser() would fix it.

Why store the token in an httpOnly cookie instead of localStorage?Auth and security

JavaScript cannot read an httpOnly cookie, so an XSS bug cannot exfiltrate the token. SameSite=Lax stops other sites from sending it on cross-site POSTs, which covers the main CSRF case.

How do you prevent CSRF?Auth and security

Only through SameSite=Lax and JSON APIs. There is no CSRF token or Origin check, so a compromised sibling subdomain could still make same-site requests. Adding an Origin check in middleware would be cheap.

How do you stop one college seeing another's data?Auth and security

Every college-scoped query filters by the caller's college_id, and getColleague() is the single entry point for acting on another user. Cross-college lookups return 404, so the response doesn't confirm the resource exists. I verified profile, connect and thread lookups across colleges.

What is weak about your rate limiter?Auth and security

It is in memory and per process, it counts successes as well as failures, and its IP comes from X-Forwarded-For, which a client can set. I verified that changing the header resets the login limit. I would trust only the proxy's appended value and add a per-account counter.

How do you prevent user enumeration at login?Auth and security

Same error message for unknown email and wrong password, and bcrypt.compare runs against a dummy hash when the email doesn't exist, so timing matches. Registration still returns 409 for a taken email, which is a remaining enumeration path.

Why bcrypt with cost 10, and why the 72-character limit?Auth and security

bcrypt is deliberately slow and salted. Cost 10 is a reasonable default for a demo; I'd raise it or move to argon2id in production. bcrypt ignores input past 72 bytes, so longer passwords are rejected rather than silently truncated.

What stops a javascript: link in a profile?Auth and security

The url validator only accepts http: and https:, and React escapes all rendered text. I verified a javascript: LinkedIn URL is rejected with 422.

What happens if JWT_SECRET is missing in production?Auth and security

getSecret() throws, so signing fails and verifySession() treats every token as invalid; nobody can log in. That is fail-closed, but the error is hidden by the catch in verifySession(), which makes it confusing to debug.

Is there anything insecure about the public demo?Auth and security

Yes. The seed creates a platform admin with a published password and the login page has one-click demo buttons, so on any public deployment that seeds demo data anyone can sign in as platform admin. Fine for a portfolio demo, not for real data; SEED_DEMO_DATA=false turns it off.

What did your probes find in authorization?Auth and security

Middleware used to gate admin routes on the role inside the JWT. Demotion was safe because requireRole() re-checks the database, but a promoted admin was blocked until they logged in again. I removed that gate so middleware only authenticates, and the database decides authorization.

How does the UI handle loading, empty and error states?Frontend

useApi() returns { data, error, loading, reload }, and pages render SkeletonList, EmptyState or ErrorState with a retry button from components/ui.js.

How do forms show server-side validation errors?Frontend

api() throws ApiError with details; forms keep them in state and pass errors.<field> to Field, which renders the message under the input.

How do you avoid a request per keystroke in search?Frontend

useDebounce(q, 300) delays the query until typing pauses, and the effect uses a cancelled flag so a slow earlier response cannot overwrite a newer one.

How does chat avoid showing a message twice?Frontend

Sent messages are appended immediately and polling may return them again, so appendMessages() filters out ids already in a Set, and the poll cursor advances to the last id.

What accessibility work is there?Frontend

Labelled inputs via Field, aria-current on nav links, role="dialog" and Escape-to-close on modals, an aria-live toast region, aria-busy skeletons and screen-reader text on badge counts.

Tell me about a time you found a bug in your own work.Behavioral hooks

While preparing these docs I suspected the nav badge and the connections page disagreed, so I wrote a check that deactivates a user who had a pending request. The badge said 1 and the list said 0. The cause was a missing is_active join in /api/summary; I added the join and the check now passes.

Tell me about a trade-off you made deliberately.Behavioral hooks

Polling over WebSockets: it works on free hosting and is simple to reason about, at the cost of latency and request volume. I'd revisit it once there is a Redis-backed multi-instance setup.

How do you decide what to cut?Behavioral hooks

I kept features that could work end to end with real data and removed pages that were only mock UI. A smaller system that is correct is easier to extend than a large one full of stubs.

How did you use AI tools on this project?Behavioral hooks

As an accelerator for the rebuild, with me reviewing, running and testing the result. I'd rather say that plainly and show I can explain and change any file.

What are you most proud of?Behavioral hooks

That revocation and tenant isolation are structural: one helper for identity, one for cross-user access, and constraints in the schema, rather than checks sprinkled around that someone could forget.

What runs in middleware and what does not?

Signature/expiry check of the JWT, the public-API allowlist, the superadmin gate for platform paths, superadmin confinement and security headers. College-admin authorization is not done there. Nothing that touches the database, because middleware runs on the Edge runtime.

Where is the database opened, and how many connections exist?

getDb() in lib/db.js calls openDatabase() from database/init.js once per process and caches the handle on globalThis, so there is one connection per server process.

What three pragmas are set and why?

journal_mode = WAL (readers do not block the writer), foreign_keys = ON (SQLite has them off by default) and busy_timeout = 5000 (wait up to 5 s for a lock instead of failing).

What is in the JWT?

sub = user id, role, cid = college id, iat and exp (7 days), signed HS256.

Why is the user re-read from the database on every request?

So deactivation, role changes and college deactivation take effect immediately even though the JWT is still valid.

A user from College A requests /api/profiles/<id of a College B user>. What happens?

404 "Profile not found", because the query filters u.college_id = @college. 404 rather than 403 so it does not reveal the user exists.

How is SQL injection prevented in search?

All values are bound parameters, and LIKE input has \, % and _ escaped with ESCAPE '\', so % searches literally (verified: 0 results).

How does profiles/me PUT build a dynamic UPDATE safely?

validate() returns only keys declared in PROFILE_RULES, so the column names interpolated into SET come from a whitelist; values are named parameters.

What does validate() do with an empty optional string?

Stores null (or false for a bool) if the key was present; omits the key if it was absent. With partial: true, required checks are skipped.

Why do login failures for unknown emails still call bcrypt?

To make response time the same as for a wrong password, so timing does not reveal which emails exist.

What are the three rate limits?

Login 10 per 15 min per IP+email, register 5 per 10 min per IP, password change 5 per 15 min per user, all fixed-window in memory.

How can the login rate limit be bypassed?

By sending a different X-Forwarded-For value, since clientIp() trusts it; also by rotating the email part of the key.

What makes the RSVP capacity check safe?

The count and insert run in one better-sqlite3 transaction, which is synchronous and holds the write lock, so no other request can interleave in the same process.

What prevents a double RSVP independently of the code?

The composite primary key (event_id, user_id) on event_rsvps.

What happens when A sends a connection request to B, who already requested A?

The POST finds B's pending row via findConnection() and accepts it instead of inserting a second row, and notifies B.

Who can accept a connection via PATCH?

Only the addressee of a pending request; otherwise 409.

List the mentorship transitions.

accept and decline: mentor, pending -> accepted/declined. complete: either party, accepted -> completed. cancel: mentee, pending -> row deleted.

Why does accepting a mentorship touch the connections table?

Messaging requires an accepted connection, so acceptance creates one or accepts a pending one, letting the pair message.

How does chat polling avoid duplicates?

It polls with ?after=<last message id>, and appendMessages() filters ids already in a Set.

Why can a platform admin not open /dashboard/directory?

Middleware redirects superadmins to /dashboard/platform for any page except /dashboard/settings, and returns 403 for college APIs; they have no college.

Which database constraint encodes "platform admins have no college"?

CHECK ((role = 'superadmin') = (college_id IS NULL)) on users.

What happens to members when a college is deactivated?

getCurrentUser() requires c.is_active = 1, so their next request is 401; login returns 403; the college disappears from /api/colleges. No rows are deleted.

Why is there no admin role check in middleware?

The JWT keeps the role from login, so a gate there blocked newly promoted admins until they signed in again. Authorization for /api/admin is done by requireRole("admin") against the database, which handles both promotion and demotion immediately.

Why does /api/summary join users?

So the badge excludes pending requests and unread messages from deactivated users, matching the Connections page. Before the fix the badge could say 1 while the page showed 0.

What happens if two people register the same email at the same instant?

Both pass the SELECT 1 ... WHERE email = ? check; the second insert violates UNIQUE, which handler() turns into a 500 rather than a 409.

Why does database/init.js throw on an old database instead of migrating?

The old users table has a CHECK constraint that SQLite cannot alter in place, and the data is demo-only, so it asks for npm run db:reset.

What would you change first to run two instances?

Move to PostgreSQL (shared state, row locks for RSVPs), move rate-limit buckets to Redis, and push or pub/sub for chat.

Why does lib/client.js not redirect on 401 from /api/auth/*?

A 401 from login means wrong credentials, which the form must display, not a session expiry.
